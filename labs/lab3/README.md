# Лаб 3 — harness (для преподавателя)

Автопроверка к лабораторной «Конвейер доставки (CI/CD + DevSecOps)», Раздел 3.
Общий фреймворк лаб — [`../CLAUDE.md`](../CLAUDE.md). Пакет самодостаточный, движок
(`labs/trainer/`) его подхватывает автоматически.

## Модель

Субстрат — **git-репозиторий с CI-конвейером** (GitHub Actions), кластер Kubernetes
не нужен. Студент строит для example-voting-app пайплайн `lint → test → build → scan
→ publish`. «Проверить» валидирует **состав конвейера** (стадии, стратегия тегов,
DevSecOps-гейты, промоушен, DORA), а не точный YAML — контракты method-blind.

Автопроверка — ворота допуска, не балл. Балл на защите (см. `../CLAUDE.md`).

## Файлы

| Путь | Роль |
| --- | --- |
| `seed.py` | ИСУ → параметры варианта (canary, схема тегов, сканеры) |
| `content.py` | заголовок, задания, подсказки по контрактам, ярлыки |
| `checks/lib.sh` + `checks/NN_*.bats` | контракты (bats, TAP, ASCII-имена) |
| `scaffold/` | дерево рабочей директории (`.github/workflows/ci.yml` с TODO) |
| `Makefile` | `seed` / `check` / `check-suite` / `clean` |

## Ограничение движка

Виджет статуса кластера в тренажёре завязан на `kubectl` — для этой лабы кластера нет,
поэтому он всегда показывает «кластер не найден». На проверки это не влияет (они читают
файлы конвейера), но на странице статус-строку по CI-лабе можно игнорировать.
