# Лаб 1 — harness (для преподавателя)

Автопроверка, тренажёр и защита к лабораторной «Контейнеры (Docker)».
Задание студента: [`../../Лабораторные/Лаб. 1 Работа с контейнерами.md`](../../Лабораторные/Лаб.%201%20Работа%20с%20контейнерами.md).
Общий фреймворк лаб — [`../CLAUDE.md`](../CLAUDE.md).

## Модель

Приложение живёт на **хостовом Docker**; студент поднимает его сам (`docker compose`) —
это и есть навык. Страница-тренажёр только **валидирует состояние**, ничего не поднимает.

- **Тренажёр** — глобальный (`labs/trainer/`, `make trainer` из `labs/`), один на все
  лабы; выбери «Лаб 1» в селекторе. Слева задания с подсказками, справа файловое дерево
  рабочей директории, редактор и встроенный терминал (ttyd, стартует в `workdir/`).
  «Проверить» прогоняет контракты против текущего состояния Docker.
- **Проверка автором** — эталона в репо нет (иначе студент его применит). Поднимаешь
  корректное решение локально (не коммитишь, `solution/` в `.gitignore`) и гоняешь `make check`.

Автопроверка — **ворота допуска**, не балл. Балл ставится на защите (см. фреймворк
`../CLAUDE.md`). Анти-GPT-слой защиты (авто-вопросы + live break-fix) в репозитории пока
не реализован.

## Против списывания

- **Сид от ИСУ** (`seed.py`) привязывает параметры (проект, iframe-URL, бюджет размера)
  и canary-токен к личности.
- **Контракты слепы к способу** — проверяется исход (образ, отданная страница, размер,
  форма git-истории), не текст Dockerfile.
- **git-коммит и тег** фиксируют работу во времени; canary-токен зашит в метку образа,
  страницу и сообщение тега.
- GPT проходит ворота — это ожидаемо; понимание проверяется на защите (живой канал).

## Файлы

| Путь | Роль |
| --- | --- |
| `seed.py` | ИСУ → параметры варианта (открытая механика) |
| `Makefile` | `seed` / `check` / `check-suite` / `clean` (глобальные `setup`/`trainer` — в `labs/Makefile`) |
| `content.py` | заголовок, задания, подсказки по контрактам, ярлыки контрактов (движок тренажёра) |

| `scaffold/` | дерево-шаблон рабочей директории (комментарии, без решения) |
| `workdir/` | рабочая зона студента: засев из `scaffold/` (в `.gitignore`) |

## Запуск

```bash
cd ..            # labs/
make setup       # хостовые зависимости + venv (mac: brew)
make trainer     # http://localhost:8899 → выбери «Лаб 1» в селекторе
# — проверка из каталога lab1 (приложение и образы поднимаешь сам):
git clone https://github.com/dockersamples/example-voting-app
cd example-voting-app
docker compose -p vote-XXXX -f docker-compose.images.yml up -d   # имя проекта = seed PROJECT
cd -
make check ISU=<ису>                            # все контракты
make check-suite SUITE=03_custom ISU=<ису>      # быстрый прогон одного задания
```

Проверки задания 5 (git) читают репозиторий по переменной `REPO` (по умолчанию
`workdir/example-voting-app`). Если клон лежит в другом месте — задай `REPO=<путь>`
в окружении перед `make check`.

## Требования

Хост: `docker` (с compose v2), `git`, `curl`, `bats`, `jq`, `python3`+`flask`,
`ttyd`, `coreutils` (даёт `gtimeout`). Ставит `make setup`.

## Известное ограничение тренажёра

Виджет «доступность кластера» в движке (`trainer/app.py`, `check_job`) жёстко завязан
на `kubectl cluster-info`: перед прогоном контрактов он проверяет наличие Kubernetes-
кластера. Для Docker-лабы кластера нет — виджет покажет «кластер не найден» и заблокирует
кнопку «Проверить» на странице. Движок общий и в рамках этой лабы **не правится** (см.
ограничения фреймворка). Обходной путь — гонять контракты из CLI: `make check ISU=<ису>`
и `make check-suite SUITE=NN_name ISU=<ису>` из каталога `lab1/`. Сами контракты
Docker-совместимы и от `kubectl` не зависят.

## Статус

Пакет собран статически по эталону Лаб 2 (структура, имена целей, тон). Контракты
Docker-совместимы, foreground, ASCII-имена, `_to` портируемый. **Требует end-to-end
прогона на живом Docker** (эталонное решение автора, `make check ISU=<любой>` зелёным):
проверить точный путь к `templates/index.html` внутри образа
`dockersamples/examplevotingapp_vote`, реальные размеры образов под бюджет
`SIZE_BUDGET_PCT` и порядок публикации портов при `serve_and_fetch`.

> Важное правило проверок (см. `../CLAUDE.md`): **никаких фоновых процессов в bats**.
> Все обращения к сервисам — foreground: `curl` к опубликованному порту и одноразовый
> контейнер (`serve_and_fetch`), снимаемый сразу после запроса.
