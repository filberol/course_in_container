# Фреймворк лабораторных

Глобальный workspace для всех лаб. Движок тренажёра пишется один раз (`labs/trainer/`),
каждая лаба — самодостаточный пакет `labs/labN/`, который движок подгружает.
Читать перед созданием новой лабы. Эталон — `labs/lab2/`. Стиль текста — как в деках
лекций (активный залог, без филлеров и fake-elevation).

## Педагогическая модель (инварианты)

- **Сквозное приложение.** Все лабы ведут одно `example-voting-app`, каждая добавляет
  слой: Лаб1 контейнеризация → Лаб2 оркестрация → Лаб3 CI/CD + DevSecOps → Лаб4 IaC +
  наблюдаемость + надёжность (капстоун).
- **Сдаётся репозиторий, не отчёт.** Оценивается воспроизводимое состояние.
- **Два уровня доверия.** Локальный тренажёр недоверенный (мгновенный фидбэк); прогон
  на защите доверенный. Автопроверка это **ворота допуска, а не балл**. Балл на защите.
- **Анти-чит.** Сид от ИСУ (параметры + canary-токен); контракты слепы к способу;
  evidence-хеш + git-коммит. GPT проходит ворота — принято; понимание ловит только
  живой канал: авто-вопросы из артефакта + сид-сценарий live break-fix.
- **Веса балла:** ворота(+evidence) / вопросы / break-fix (в Лаб2 — 3/5/4 из 12).

## Архитектура (глобальный host-workspace)

- **Кластер/инфра — на хостовом Docker, не в DinD** (kind-in-DinD падает на cgroup v2).
  Студент поднимает кластер сам в терминале — реальные `kind`/`kubectl` это навык.
- **Один тренажёр на все лабы** (`labs/trainer/`, `make trainer`): страница на хосте
  со селектором лаб, редактором манифестов и встроенным терминалом (ttyd). «Проверить»
  **только валидирует** состояние активной лабы, кластер не создаёт.
- **Лаба = контент-пакет.** Движок обнаруживает `labs/lab*/` (по наличию
  `content.py` + `seed.py` + `Makefile`), подгружает её задания/сид, гоняет её
  контракты `make -C labN`. Чтобы добавить лабу — движок трогать не нужно.

## Раскладка

```
labs/
  CLAUDE.md          # этот файл
  Makefile           # setup, trainer (глобальные)
  trainer/           # ДВИЖОК (один на все лабы; при добавлении лабы не трогается)
    app.py           #   Flask: обнаружение лаб, /api/state|check|cluster|…, стрим лога
    index.html       #   UI: селектор лаб, редактор (CodeMirror), терминал, чипы
    vendor/          #   CodeMirror вшит (офлайн, без CDN)
    serve.sh setup.sh
  lab2/              # ПАКЕТ ЛАБЫ (самодостаточный)
    seed.py          #   params(isu) + CLI (--env/--get); детерминированно от ИСУ
    content.py       #   TITLE, TERMINAL_HINT, TASKS, CHECK_LABELS
    Makefile         #   seed/check/check-suite/render/selftest/clean
    checks/lib.sh    #   хелперы (kc, _to, inpod, cast_vote, read_count, lb_hostnames)
    checks/NN_*.bats #   контракты по заданиям (TAP, ASCII-имена)
    scaffold/        #   шаблон рабочей директории (дерево файлов-заготовок, комментарии)
    workdir/         #   рабочая зона студента: засев из scaffold/ с подстановкой сида (в .gitignore)
    solution/        #   [преподаватель] эталон по сиду + render.py; НЕ входит в шаблон студента
    README.md
  lab3/ …            # следующая лаба — такой же пакет
```

## Правила написания контрактов (жёсткие, выстраданы)

1. **ASCII-имена тестов.** `@test "NN.N short english"`, русское — комментарием над
   тестом. bats коверкает не-ASCII имена в локали C → «unknown test name».
2. **Никаких фоновых процессов в bats.** Фоновый `kubectl port-forward` (любой `&`)
   наследует служебный дескриптор bats и не отпускает — прогон молча виснет до
   таймаута. К сервисам ходить foreground-хелпером `inpod` (эфемерный под, вывод
   через `kubectl logs` после завершения — надёжнее `run --rm -i`). Меняющееся во
   времени состояние семплировать foreground-циклом.
3. **Проверять исход, не реализацию.** Контракт — наблюдаемое свойство результата,
   не текст манифеста (StatefulSet и Deployment+PVC проходят одинаково). Точное
   совпадение — только для сид-якорей личности (canary, назначенные порт/размер).
4. **Переносимые таймауты.** Внешние вызовы оборачивать в `_to N cmd`
   (timeout/gtimeout/без ограничения). Голый `timeout` нельзя — на macOS его нет.
5. **Стрим + подсчёт через файл, не висячий пайп.**
   `bats --tap --timing checks/ | tee .scorecard.tap` — TAP стримит по-тестово.
   Тренажёр читает `.scorecard.tap` сам (красит чипы); CLI-`check` — inline `grep '^not ok'`.
6. **Проверка по одному заданию.** `check-suite SUITE=NN_name` гоняет один файл.
   Движок сам мапит id задания «NN» → файл `NN_*.bats`.
7. **Контракт env.** Проверки читают параметры из окружения (NS, CANARY, …),
   экспортируемого Makefile через `set -a; eval $(seed.py --env)`. `lib.sh` страхует
   `: "${NS:?…}"`.

## Что движок ждёт от лабы (контракты пакета)

- **`seed.py`** — `params(isu) -> dict` + CLI (`--env`, `--get KEY`, таблица).
  Детерминированно `sha256(isu + SALT)`, механика открытая. Обязательно: canary-токен
  (якорь личности) + outcome-параметры + `BREAKFIX_ID`. `NS` — namespace для статуса.
- **`content.py`** — `TITLE` (для селектора), `TERMINAL_HINT` (команды поднятия
  кластера, показываются в терминал-хедере), `TASKS` (id, title, body, hints[],
  checks[]), `CHECK_LABELS` (id контракта → ярлык чипа). `${NS}` и т.п. — из сида.
- **`Makefile`** — цели `check` / `check-suite SUITE=… ISU=…` (пишут `.scorecard.tap`
  в корне лабы), `render`, `selftest`. Движок вызывает их через `make -C labN`.
- **`scaffold/`** — дерево-шаблон рабочей директории (файлы только с комментариями,
  без решения). Движок засевает из него `workdir/` с подстановкой сида; студент правит
  дерево (создание/удаление файлов и папок) в редакторе, терминал стартует в `workdir/`.
- **`solution/`** — шаблон по сиду + `render.py`; `make selftest` = render+apply+check.
  Способ выбирать намеренно method-blind. **Вырезается из студенческого шаблона.**

Движок (`trainer/`) при добавлении лабы **не меняется**.

## Как добавить лабу (напр. Лаб 3)

1. `cp -r lab2 lab3` и вычистить под новый слой.
2. `seed.py`: новый `SALT` + параметры слоя + canary + `BREAKFIX_ID`.
3. `content.py`: `TITLE`, `TERMINAL_HINT`, `TASKS`/`CHECK_LABELS` (по-русски).
4. `checks/NN_*.bats`: контракты (ASCII, method-blind, foreground-хелперы).
5. `scaffold/`: дерево-шаблон рабочей директории. `solution/`: эталон по сиду;
   `make selftest` должен пройти end-to-end зелёным.
6. Handout студента в `Лабораторные/…md` в формате Лаб 1; §4 — поток тренажёра.
7. Готово: лаба появляется в селекторе тренажёра автоматически.

## Проверка перед сдачей лабы

- `make selftest ISU=<любой>` зелёный end-to-end на живом кластере.
- Ни одного `&` в `checks/`. Все имена тестов ASCII.
- `make trainer` (из `labs/`) → лаба видна в селекторе, «проверить это задание»
  краснеет/зеленеет, лог стримит по контрактам.
