# Лаб 2 — harness (для преподавателя)

Автопроверка, тренажёр и защита к лабораторной «Оркестрация в Kubernetes».
Задание студента: [`../../Лабораторные/Лаб. 2 Работа с кластерами.md`](../../Лабораторные/Лаб.%202%20Работа%20с%20кластерами.md).
Общий фреймворк лаб — [`../CLAUDE.md`](../CLAUDE.md).

## Модель

Кластер живёт на **хостовом Docker**; студент поднимает его сам (`kind`/`kubectl`) —
это и есть навык. Страница-тренажёр только **валидирует состояние**, не создаёт кластер.

- **Тренажёр** — глобальный (`labs/trainer/`, `make trainer` из `labs/`), один на все
  лабы; выбери «Лаб 2» в селекторе. Слева задания с подсказками, справа файловое дерево
  рабочей директории, редактор и встроенный терминал (ttyd, стартует в `workdir/`).
  «Проверить» прогоняет контракты против текущего кластера.
- **Проверка автором** — эталона в репо нет (иначе студент его применит). Поднимаешь
  корректное решение локально (не коммитишь, `solution/` в `.gitignore`) и гоняешь `make check`.

Автопроверка — **ворота допуска**, не балл. Балл ставится на защите (см. фреймворк
`../CLAUDE.md`). Анти-GPT-слой защиты (авто-вопросы + live break-fix) в репозитории пока
не реализован.

## Против списывания

- **Сид от ИСУ** (`seed.py`) привязывает параметры и canary-токен к личности.
- **Контракты слепы к способу** — проверяется исход, не текст манифеста.
- **git-коммит** фиксирует работу во времени.
- GPT проходит ворота — это ожидаемо; понимание проверяется на защите (живой канал).

## Файлы

| Путь | Роль |
| --- | --- |
| `seed.py` | ИСУ → параметры варианта (открытая механика) |
| `Makefile` | `seed` / `check` / `check-suite` / `clean` (глобальные `setup`/`trainer` — в `labs/Makefile`) |
| `content.py` | заголовок, задания, подсказки по контрактам, ярлыки контрактов (движок тренажёра) |
| `checks/lib.sh` | хелперы: `kc`, `_to`, `inpod`, `cast_vote`, `read_count`, `lb_hostnames` |
| `checks/NN_*.bats` | контракты заданий (bats, TAP, ASCII-имена) |
| `scaffold/` | дерево-шаблон рабочей директории (комментарии, без решения) |
| `workdir/` | рабочая зона студента: засев из `scaffold/` (в `.gitignore`) |

## Запуск

```bash
cd ..            # labs/
make setup       # хостовые зависимости + venv (mac: brew)
make trainer     # http://localhost:8899 → выбери «Лаб 2» в селекторе
# — проверка из каталога lab2 (кластер и манифесты поднимаешь сам):
kind create cluster --name lab2
kubectl apply -f <свои-манифесты>
make check ISU=<ису>                           # все контракты
make check-suite SUITE=04_probes ISU=<ису>    # быстрый прогон одного задания
```

## Требования

Хост: `docker`, `kind` ≥ 0.23, `kubectl` ≥ 1.30, `bats`, `jq`, `python3`+`flask`,
`ttyd`, `coreutils` (даёт `gtimeout`). Ставит `make setup`.

## Статус

Все пять заданий реализованы и проверены end-to-end на живом кластере (ISU 123456):
все контракты зелёные, полный прогон ~1 мин, по одному заданию — секунды
(01≈4с, 02≈4.5с, 03≈9с, 04≈3с, 05≈36с). Схема сверена с актуальным
`example-voting-app` (redis-хост `redis`, `postgres:15-alpine`, форма POST `/` поле
`vote`, «Processed by container ID …»).

> Важное правило проверок (см. `../CLAUDE.md`): **никаких фоновых процессов в bats** —
> фоновый `kubectl port-forward` наследует служебный дескриптор bats и вешает прогон.
> Все обращения к сервисам — foreground через `inpod` (эфемерный под + `kubectl logs`).
