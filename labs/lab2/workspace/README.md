# Воркспейс Лаб 2

Собираемый контейнер со всем инструментарием и веб-фронтом. Студент поднимает его
и выполняет работу внутри — `kind`, `kubectl`, `bats`, `python3+pyyaml`, `jq`, `git`,
`make` уже стоят. Ставить на хост ничего не нужно, кроме Docker.

## Запуск

```bash
cd labs/lab2/workspace
docker compose up --build -d
# открыть http://localhost:8080  — VS Code в браузере
```

Порт хоста занят? Задайте свой:

```bash
CODE_PORT=8899 docker compose up -d     # фронт на http://localhost:8899
```

Внутри (терминал браузера) harness лежит в `/work`:

```bash
kind create cluster --name lab2
make check ISU=<ваш_ИСУ>
```

Остановить: `docker compose down` (образы `kind` переживают рестарт — они в томе `dind-data`).

## Почему так

- **Docker-in-Docker, `--privileged`.** Контейнер держит собственный `dockerd`, `kind`
  поднимает кластер внутри него. Поэтому `kubectl` достаёт API-сервер по `127.0.0.1`
  без хостовой сети — это работает и на macOS/Docker Desktop, где проброс хостового
  сокета ломает адресацию `127.0.0.1`.
- **Одинаковое окружение.** Студент и преподаватель (`make grade`) работают в
  идентичном образе — «работает на моей машине» исключено.
- **Изоляция.** Кластер и образы живут внутри воркспейса, хост не засоряется.

## Требования и оговорки

- Docker Desktop с памятью ≥ 4 ГБ (kind + приложение).
- Фронт слушает только `127.0.0.1:8080`, `--auth none` — для локальной работы.
  Для доступа по сети задайте `--auth password` и переменную `PASSWORD` в
  `entrypoint.sh`/compose.
- **Apple Silicon:** часть образов `example-voting-app` собрана под amd64 и пойдёт
  через эмуляцию (медленно). При проблемах используйте multi-arch аналоги или
  соберите сервисы под arm64.
- Первая сборка тянет `kubectl`/`kind`/`code-server` из сети — нужен интернет.
